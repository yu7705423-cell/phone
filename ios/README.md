# iOS 外壳

把这个项目装成一只 iPhone 上的 app。产物是**未签名**的 `.ipa`，签名由使用者自己完成。

## 它是什么

一只铺满屏幕的 `WKWebView`，从网络地址载入本项目的网页。整只 app 只有三个 Swift 文件，
不含任何网页资源。

**改了网页代码，在 app 里摇一摇选「重新载入」就是新的，不需要重新打包，也不需要重新安装。**
代价是打开与刷新都需要网络。本项目的 Service Worker 只负责推送通知，不缓存任何资源
（见 `sw.js`），所以即使把资源打进包里也一样离线打不开，这里没有额外损失。

## 相比在 Safari 里加到主屏幕，多了什么

| | 加到主屏幕 | 这只 app |
|---|---|---|
| 本机数据 | 七天未打开就可能被系统清掉 | 登记为 app-bound 域名，不受这条约束 |
| 后台保活 | 切后台很快被冻结 | 声明了后台音频，那段无声循环音频能继续跑 |
| 元素全屏 | 受限 | 已开启，读书与看片的全屏可用 |
| 导出备份 | 走浏览器下载 | 接住下载并弹出分享面板，可存到「文件」 |
| 站点地址 | 固定 | 可在应用内修改 |

「七天未打开就可能被系统清掉」那一条是最要紧的：角色卡、聊天记录、记忆全部存在
IndexedDB 里。`Info.plist` 的 `WKAppBoundDomains` 就是为它写的。

## 打包

### 在 GitHub 上打

仓库的 Actions 里有「打包 ipa」。手动运行，填好网页地址即可，产物在运行记录的
artifact 里。推一个 `ios-v1.0.0` 这样的标签会同时建一个 Release。

网页地址默认指向 GitHub Pages（`https://yu7705423-cell.github.io/phone/`）。
使用前需要先在仓库设置的 Pages 一节里把来源设为本分支，否则该地址不存在。

### 在自己的 Mac 上打

需要 Xcode 命令行工具。

```
APP_URL=https://你的地址/ ios/build.sh
```

产物在 `ios/build/phone-unsigned-<版本>.ipa`。

可用的环境变量：`APP_URL`、`BUNDLE_ID`、`DISPLAY_NAME`、`VERSION`、`BUILD_NUM`、
`MIN_IOS`、`APP_BOUND`。

## 安装

ipa 未签名，需要自己签。三种常见办法：

| 工具 | 需要 | 有效期 |
|---|---|---|
| Sideloadly / AltStore | 一个 Apple ID | 免费账号 7 天，付费开发者账号 1 年 |
| TrollStore | 系统版本在其支持范围内 | 永久 |

免费账号签的 app 到期后需要重新签一次，**重签的是同一个 ipa，不必重新打包**；
网页代码的改动仍然只需要刷新。重签不会清除本机数据，前提是包标识（`BUNDLE_ID`）不变。

## 应用内的设置

摇动设备打开外壳菜单：

- **重新载入** —— 回源取一遍网页代码
- **清除网页缓存后载入** —— 只清 HTTP 缓存，不动 IndexedDB 与 localStorage
- **设置站点地址** —— 改成别的地址，例如局域网内自己起的 `http://192.168.1.10:8000`

改到打包时登记之外的域名后，上面那条数据保护会关闭，应用内会提示一次。要长期使用
别的地址，重新打包一次并把 `APP_URL` 设成它。

## 已知的限制

- 只有竖屏。横着看的那一套由网页自己用 CSS 旋转，交给系统转会变成转两次。
- 无法离线打开。
- Web Push 在 `WKWebView` 里不可用，通知只在 Safari 加到主屏幕时有效。
